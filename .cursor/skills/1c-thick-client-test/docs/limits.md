# Ограничения

Только Linux и толстый клиент в режиме обычного приложения. Управляемые формы навык не проверяет.

Щелчок по координате и `windowclose` относятся только к стартовым окнам из белого списка. `windowclose` после снимка формы документа или отчёта роняет `1cv8` (`GdkWindow unexpectedly destroyed`). Такую форму закрывает код исполнителя, после маркера `snap-done`.

Диалог «Защита от опасных действий» подтверждается только до открытия обработки, только для `.epf` из `out/thick-client-check/cache/` с заранее посчитанным sha256, и только вместе со снимком в отчёте. Кнопка ищется как отдельное окно с заголовком «Да» или «Yes». У диалога 1С такой кнопки нет: нажимается левая нижняя доля окна. Альтернатива — отключить защиту у тестового пользователя силами администратора.

`collector` у `Печать` вызывает `ТабличныйДокумент.Напечатать()` внутри конфигурации до того, как табличный документ попадёт в массив. Это не форма «Печать документов», но на базе с принтером лист уйдёт на печать.

В обычном приложении `ПолучитьОкна()` возвращает `Неопределено`. Путь через форму печати помечен в шаге и без реквизита `ПечатныйДокумент` на уже открытой форме файл не даёт.

УПП 1.3 на платформе 8.3.14 не доходит до сценария. При старте серверный модуль `ПользователиСервер`, строка 248, читает `Метаданные.ОсновнаяРоль`, и платформа отвечает «Недопустимо использование свойства "ОсновнаяРоль"». Пользователь ИБ это не обходит: строка выполняется до открытия обработки. `ibcmd` 8.3.14 пользователя ИБ не создаёт. Чтобы запуск прошёл, конфигурации нужна сборка, в которой это свойство разрешено (в 8.3.14 вместо него список `ОсновныеРоли`), либо платформа, на которой свойство ещё допустимо. Роль и пользователь ИБ сами по себе старт не открывают.

Сценарий не проводит и не записывает документы. `shellcheck` в образе может отсутствовать: тогда в отчёте «не проверено» и текст ошибки, пакеты агент не ставит.
