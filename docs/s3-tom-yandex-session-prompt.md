## Задача сессии

Сделать **отдельное расширение конфигурации** для хранения файлов БСП в **S3 (Yandex Object Storage)** по модели [S3_SSL](https://github.com/BlizD/S3_SSL).

**Не использовать** платформенный UI «Список хранилищ двоичных данных → S3» — нужен именно **слой томов БСП** (как S3_SSL / Habr).

**Не смешивать** с бизнес-расширением `Расширение1Коммерция` без явной необходимости. Рекомендуемое имя: **`S3ХранениеФайлов`** (или `s3_ХранениеФайлов` по аналогии с S3_SSL).

## Ожидаемый эффект (тома / S3)

| Показатель | Значение |
|---|---|
| Сокращение логического размера ИБ | **~5,0–5,5 Гб** (~45% от текущих 11,8 Гб) |
| Итог после переноса (без очистки почты) | **~6,2–6,7 Гб** |
| Объект-источник | `Справочник.ХранилищеДвоичныхДанных` |
| Физический `.1CD` | может не уменьшиться без **сжатия ИБ** |
| Объём в S3 | **6–7+ Гб** (дедуп в ИБ при переносе в тома не сохраняется — у каждой версии свой файл) |

|---|---:|---|

## Референс S3_SSL — состав расширения

Из репозитория [BlizD/S3_SSL](https://github.com/BlizD/S3_SSL) (`src/`):

| Компонент | Назначение |
|---|---|
| `s3_API` | S3 API: Put/Get/Delete, AWS4-HMAC-SHA256 |
| `s3_КоннекторHTTP` | HTTP-клиент (Connector vbondarevsky) |
| `Enums/s3_ТипыХранилищ` | Тип «Объектное S3» |
| `Catalogs/ТомаХраненияФайлов` | +реквизиты S3, форма элемента |
| Перехваты `&ИзменениеИКонтроль` | см. ниже |
| `Reports/ПроверкаЦелостностиТома` | Проверка целостности S3-тома |

**Важно:** S3_SSL заточен под **Документооборот 2.1** (есть `Catalogs/Файлы`, `ФайловыеФункции*`). В УТ+CRM часть модулей **другие** — нужен diff и адаптация, не слепое копирование.

### Модули для перехвата (ориентир S3_SSL / Habr)

Проверить наличие и сопоставить с `src/cf/`:

- `РаботаСФайламиВызовСервера` — в S3_SSL; в УТ может отличаться набор
- `РаботаСФайламиСлужебныйВызовСервера` — **есть в УТ**, ключевой
- `РаботаСФайламиСлужебный` — **есть в УТ**
- `РаботаСФайламиВТомахСлужебный` — `ДобавитьФайл`, `ПолныйПутьТома`, `УдалитьФайл`
- `ФайловыеФункции` / `ФайловыеФункцииСлужебный` — могут **отсутствовать** в УТ

Точка перехвата — **самый нижний слой**, где blob превращается в файл на диске (как в [Habr](https://habr.com/ru/companies/vk/articles/892824/)).

### Ключевые файлы УТ+CRM

- `src/cf/CommonModules/РаботаСФайламиВТомахСлужебный/Ext/Module.bsl`
- `src/cf/CommonModules/РаботаСФайламиСлужебныйВызовСервера/Ext/Module.bsl`
- `src/cf/CommonModules/РаботаСФайламиСлужебный/Ext/Module.bsl`
- `src/cf/Catalogs/ТомаХраненияФайлов.xml` — сейчас только `ПолныйПутьWindows/Linux`, без S3
- `src/cf/InformationRegisters/ХранилищеФайлов/Ext/ManagerModule.bsl`
- `src/cf/DataProcessors/ПанельАдминистрированияБСП/Forms/НастройкиРаботыСФайлами` — «Перенос в тома»

## Yandex Object Storage

| Поле формы тома | Значение |
|---|---|
| Тип хранилища | Объектное S3 |
| Адрес S3 | `https://storage.yandexcloud.net` |
| Контейнер (bucket) | `<имя-bucket>` — задать при настройке |
| Каталог (prefix) | например `prod/{PROJECT_SLUG}/` |
| Регион | `ru-central1` |
| Access Key ID / Secret | сервисный аккаунт YC |
| Virtual host | по документации YC (path-style vs virtual-hosted) |

Подпись: **AWS4-HMAC-SHA256** (как в S3_SSL).

**Секреты не коммитить** в репозиторий — только в настройках тома в ИБ.

## Ограничения и риски

1. Расширение S3_SSL: **«Безопасный режим» = Нет** (иначе HTTP к S3 не работает).
2. После блока 1 blob в **`ХранилищеДвоичныхДанных` (ИБ)**. Для выноса в S3:
   - включить `ХранитьФайлыВТомахНаДиске`;
   - создать S3-том;
   - штатный **«Перенос в тома»** (фоновое задание БСП, ~300k файлов, мониторинг как в блоке 1).
3. PROD: **бэкап** перед включением томов и миграцией; не перезапускать сервер 1С во время переноса.
4. При обновлении БСП/УТ — регрессия перехватов `&ИзменениеИКонтроль`.
5. Зависимость от сети/latency S3; тест на копии PROD обязателен.

## План работ

### Фаза A — анализ

1. Скачать [s3_ssl_2025.06.28.01.cfe](https://github.com/BlizD/S3_SSL/releases/download/2025.06.28.01/s3_ssl_2025.06.28.01.cfe) или изучить `src/` на GitHub.
2. Diff S3_SSL vs УТ+CRM: adopted-объекты, имена модулей.
3. Таблица перехватов: процедура → изменение → fallback для обычного дискового тома.
4. Решение: отдельное CFE `S3ХранениеФайлов` в `src/cfe/`.

### Фаза B — разработка

5. CFE: `s3_API`, `s3_КоннекторHTTP`, enum, реквизиты и форма `ТомаХраненияФайлов`.
6. Перехваты в модулях `РаботаСФайлами*` (имена УТ, не ДО).
7. `ПроверкаЦелостностиТома` под Yandex S3.
8. Валидация: `syntaxcheck` → `check_1c_code` → `review_1c_code`.

### Фаза C — DEV

9. Загрузить расширение в DEV, safe mode = off.
10. Тестовый bucket Yandex, tom «Облако S3».
11. Тест: загрузка → открытие → версия → удаление → целостность tom.
12. «Перенос в тома» на выборке 10–100 файлов.

### Фаза D — PROD

13. Бэкап PROD.
14. Подключить расширение, настроить S3-tom.
15. Включить «Хранить файлы в томах на диске».
16. Фоновый «Перенос в тома» + мониторинг.
17. «Проверить целостность» = 100%.
18. `РазмерПриложений.РассчитатьРазмерПриложения()`, сжатие ИБ, отчёт до/после.

## Что НЕ делать
