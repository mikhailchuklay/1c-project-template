# Настройка S3-томов (Yandex Object Storage) для УТ+CRM

Расширение **`Расш1КS3_S3ХранениеФайлов`** (`src/cfe/Расш1КS3_S3ХранениеФайлов/`) добавляет поддержку объектного хранилища S3 в стандартный механизм **томов БСП**. Используется штатный путь администрирования: «Хранить файлы в томах на диске» → «Тома хранения файлов» → «Перенос в тома».

**Не путать** с платформенным UI «Список хранилищ двоичных данных → S3» — это другой механизм.

См. также: [OpenSpec design](../openspec/changes/s3-yandex-file-storage/design.md), [session prompt](s3-tom-yandex-session-prompt.md).

---

## Предварительные условия

| Параметр | Значение |
|---|---|
| Платформа | {PLATFORM_VERSION} |
| БСП | 3.1.35.10 |
| Расширение | `Расш1КS3_S3ХранениеФайлов`, префикс `Расш1КS3_` |
| Endpoint Yandex | `https://storage.yandexcloud.net` |
| Регион | `ru-central1` |
| Подпись | AWS4-HMAC-SHA256 (path-style, как в S3_SSL) |

Расширение **независимо** от `Расширение1Коммерция`. Секреты (Access Key / Secret Key) **не хранятся в git** — только в реквизитах тома в информационной базе.

## 1. Bucket в Yandex Cloud

1. Создайте bucket в Object Storage (рекомендуется отдельный bucket на среду: `dev-{PROJECT_SLUG}`, `prod-{PROJECT_SLUG}`).
2. Создайте сервисный аккаунт с ролью **`storage.editor`** (или минимально необходимый набор: list/get/put/delete объектов в bucket).
3. Выпустите **статический ключ доступа** (Access Key ID + Secret Access Key). Сохраните Secret — повторно он не показывается.
4. Задайте **prefix** (каталог объектов), например:
   - DEV: `dev/{PROJECT_SLUG}/`
   - PROD: `prod/{PROJECT_SLUG}/`

Проверка из CLI (опционально):

```bash
aws --endpoint-url=https://storage.yandexcloud.net s3 ls s3://<bucket>/
```

## 2. Загрузка расширения в информационную базу

### DEV (файловая ИБ из `.dev.env`)

Перед загрузкой **остановите автономный сервер** (`ibsrv`), если он держит блокировку на каталог `build/ib`.

```powershell
cd D:\infobases-files\{PROJECT_SLUG}
oscript -encoding=utf-8 oscript_modules\vanessa-runner\src\main.os compileext `
  "src/cfe/Расш1КS3_S3ХранениеФайлов" "Расш1КS3_S3ХранениеФайлов"
```

После загрузки запустите `ibsrv` и **отключите безопасный режим** (обязательно для HTTP к S3):

```powershell
.\tools\dev-standalone\start.ps1
.\tools\dev-standalone\Enable-S3Extension.ps1
```

Скрипт `Enable-S3Extension.ps1` вызывает `ibcmd infobase config extension update --safe-mode=no` для запущенного `ibsrv` (нужны `IB_USER` / `IB_PASSWORD` с правом администрирования расширений).

Проверка:

```powershell
$p = (Get-Process ibsrv).Id
& "$env:PLATFORM_PATH\bin\ibcmd.exe" --pid=$p infobase config extension info --name="Расш1КS3_S3ХранениеФайлов"
```

Ожидается: `active: yes`, `safe-mode: no`.

### DEV test bucket (Yandex Cloud)

Создан автоматически в folder **onesoftmarket** (`b1gg10128o3tg9mbp6n3`):

| Параметр | Значение |
|---|---|
| Bucket | `dev-{PROJECT_SLUG}-s3` |
| Endpoint | `https://storage.yandexcloud.net/dev-{PROJECT_SLUG}-s3` |
| Prefix DEV | `dev-files/` |
| Prefix PROD (эталон для `Расш1КS3_ИмяПрефиксаРабочаяБаза`) | `prod-files/` |
| Region | `ru-central1` |
| SA | `sa-{PROJECT_SLUG}-s3-dev` |

Локальные ключи (не в git): `build/dev-s3-credentials.local.env` (`build/` в `.gitignore`).

Проверка bucket из CLI:

```powershell
yc storage s3api list-objects-v2 --bucket dev-{PROJECT_SLUG}-s3 --prefix dev-files/
```

## 3. Создание S3-тома

**Администрирование** → **Настройки работы с файлами** (или `Обработка.ПанельАдминистрированияБСП.Форма.НастройкиРаботыСФайлами`) → **Тома хранения файлов**.

1. Создайте новый элемент справочника **Тома хранения файлов**.
2. На форме (расширенной программно) выберите **Тип хранилища: S3-хранилище**.
3. Заполните поля:

| Поле | Пример (DEV) |
|---|---|
| Адрес S3 | `https://storage.yandexcloud.net/dev-{PROJECT_SLUG}-s3` |
| Имя bucket (контейнер) | *(включено в адрес — path-style, как S3_SSL)* |
| Каталог (prefix) | `dev-files` |
| Имя префикса рабочая база | `prod-files` *(на DEV должно отличаться от prefix — иначе запись в S3 блокируется)* |
| Регион | `ru-central1` |
| Идентификатор ключа доступа | см. `build/dev-s3-credentials.local.env` |
| Секретный ключ | см. `build/dev-s3-credentials.local.env` |

4. Переключатель **«Разрешить изменение настроек»** — включите только на время ввода секретов; после записи верните в «Нет» (поля станут только для просмотра).
5. Запишите элемент. Имя тома подставится автоматически: `{prefix} ({endpoint})`.

**PROD:** при необходимости отредактируйте реквизит **`Расш1КS3_ИмяПрефиксаРабочаяБаза`** — override prefix для рабочей базы (доступен только на PROD).

Дисковые тома (`Сетевая папка`) работают как раньше — перехваты срабатывают только для `ОбъектноеS3`.

### 3.1. Автотест через MCP (APA `s3_dev_probe`)

Для сквозного теста Put/Head/Get/Delete без UI и без `vcexecutecode` (который не видит модули расширений):

1. Загрузите расширение `Расш1КS3_S3ХранениеФайлов` (`compileext`), включите safe-mode=no.
2. Добавьте инструмент **`s3_dev_probe`** в справочник **`APA_Инструменты`** (см. ниже).
3. Убедитесь, что `ibsrv` запущен и опубликован `hs/mcp`.
4. Запустите:

```powershell
.\tools\dev-standalone\Invoke-S3DevProbe.ps1
# или
.\tools\dev-standalone\Invoke-DataMcp.ps1 s3-probe
```

Скрипт читает ключи из `build/dev-s3-credentials.local.env`, вызывает MCP-инструмент **`s3_dev_probe`**: находит или создаёт S3-том, загружает probe-файл, проверяет чтение и удаляет его.

Ожидаемый результат: строка `=== PASS: S3 DEV probe завершён успешно ===`.

#### Загрузка `s3_dev_probe` в `APA_Инструменты`

Файл: **`tools/dev-standalone/ИнструментыS3Тестирование.xml`**.

По [документации OneMCP](https://docs.onerpa.ru/konstruktor-mcp-serverov-1c/ustanovka.md) импорт работает **только так**:

1. Режим **1С:Предприятие** (не Конфигуратор).
2. Откройте справочник **`APA_Инструменты`**.
3. В **форме списка** этого справочника — команда **«Загрузка данных из XML»** (механизм конструктора OneMCP).
4. Укажите `ИнструментыS3Тестирование.xml`.
5. После загрузки в списке должен появиться элемент с наименованием **`s3_dev_probe`**.

**Не подходят** (часто «завершается без ошибок», но записей нет):

- Конфигуратор → загрузка конфигурации / расширения;
- «Все функции» → универсальный обмен данными БСП / EnterpriseData;
- импорт XML в другой справочник.

**Проверка после импорта:**

```powershell
.\tools\dev-standalone\Invoke-DataMcp.ps1 tools
```

В списке tools должно быть имя **`s3_dev_probe`**.

**Если XML снова не импортируется** — создайте элемент вручную в `APA_Инструменты` (см. таблицу ниже) **или** выполните автоматическую установку через MCP:

```powershell
.\tools\dev-standalone\Install-S3ApaTool.ps1
```

Скрипт создаёт `s3_dev_probe` через `vcexecutecode` (обходит UI-импорт XML). Требуется запущенный `ibsrv` и базовые инструменты OneMCP (`vcexecutecode`).

**Ручное создание** (если MCP недоступен):

| Поле | Значение |
|------|----------|
| Наименование | `s3_dev_probe` |
| Описание | Сквозной DEV-тест S3-тома (Put/Head/Get/Delete) |
| ЗапросКод | см. блок `<ЗапросКод>` в `ИнструментыS3Тестирование.xml` |
| Параметры (ТЧ) | 9 строк — см. блоки `<Параметры>` в том же XML (`Имя` / `ИмяEn` / `Описание`) |

Права: у пользователя должна быть запись в `APA_Инструменты`. При сомнениях — загрузка под полными правами / эксклюзивный доступ к ИБ.

## 4. Включение хранения в томах

В **Настройках работы с файлами**:

1. Включите **«Хранить файлы в томах на диске»** (или гибридный режим по политике).
2. Укажите созданный S3-том как целевой (порядок заполнения / правила БСП — по вашей политике).

**Не перезапускайте** сервер 1С во время массового переноса.

---

## 5. Миграция файлов («Перенос в тома»)

1. **Полный бэкап** информационной базы (обязательно на PROD).
2. Запустите **«Перенос файлов»** / «Перенос в тома» из панели администрирования БСП.
3. Мониторинг — как при блоке 1 legacy-миграции (~300k файлов на PROD; на DEV начните с 10–100 файлов).
4. По завершении выполните **«Проверить целостность»** на S3-томе — ожидается **100%** без ошибок файловой системы (для S3 используется listing через API, не `НайтиФайлы`).

### Ожидаемый эффект (PROD, после блока 1)

| Показатель | Оценка |
|---|---|
| Логическое уменьшение ИБ | ~5,0–5,5 Гб (blob из `ХранилищеДвоичныхДанных`) |
| Объём в S3 | 6–7+ Гб (дедуп SHA256 при переносе в тома **не сохраняется**) |
| Тела писем (~3,9 Гб) | **не переносятся** — не подсистема файлов БСП |

## 7. Замер размера до и после

### Логический размер (объекты конфигурации)

```bsl
// Data MCP / консоль запросов
РазмерПриложений.РассчитатьРазмерПриложения();
```

Зафиксируйте **до** и **после** миграции. Ключевой источник — `Справочник.ХранилищеДвоичныхДанных` (см. `build/size-analysis-block1-after.txt`).

### Физический файл `.1CD`

Логическое уменьшение **не обязательно** уменьшает файл базы на диске. После успешной миграции и проверки целостности:

1. Убедитесь, что нет активных фоновых заданий переноса.
2. Выполните **сжатие / перестроение** информационной базы штатными средствами 1С (отдельная операция, вне окна переноса).
3. Сравните размер `.1CD` до/после сжатия.

## 8. Откат

| Ситуация | Действие |
|---|---|
| Ошибка до переноса | Отключить «Хранить файлы в томах», удалить S3-том, отключить расширение |
| Частичный перенос | Остановить фоновое задание; восстановить ИБ из бэкапа |
| После успешного переноса | Откат = восстановление **полного** бэкапа ИБ (объекты уже в S3; обратный автоматический перенос не предусмотрен) |
| Проблемы с S3 | Проверить ключи, bucket policy, сеть; временно переключить новые файлы на дисковый том |

Объекты в bucket при откате из бэкапа **останутся** — их можно удалить вручную по prefix после согласования.

## 10. Устранение неполадок

| Симптом | Возможная причина |
|---|---|
| HTTP / доступ к S3 | Безопасный режим расширения включён |
| 403 SignatureDoesNotMatch | Неверный Secret, регион, clock skew |
| Файл не открывается | Том не S3 / неверный prefix / объект удалён в bucket |
| Целостность ≠ 100% | Прерванный перенос; объекты в S3 без записи в ИБ или наоборот |
| Блокировка при `compileext` | Запущен `ibsrv` или конфигуратор на той же ИБ |
| `cfe-borrow` на `ТомаХраненияФайлов` | **Не повторять** без восстановления `ChildObjects` — скрипт Session 2 |
