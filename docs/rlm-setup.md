# Персональный RLM: начальная настройка

Этот шаг выполняется при инициализации проекта и переносе на другое рабочее место.
Регистрация в RLM означает запись имени и пути существующей выгрузки, а не создание
информационной базы, репозитория или новой выгрузки.

## Вопросы разработчику

На dev-workplaces используется управляемая локальная версия с
`RLM_ALLOW_PASSWORDLESS_LOCAL=1`: пароль не запрашивается. На других серверах
ориентироваться на фактический ответ MCP; требование пароля не обходить.
Подтверждение пользователя для регистрации и индексации сохраняется независимо
от парольного режима. Уже имеющийся пароль записи не нужно удалять.

1. Подключить персональный RLM для этого проекта: да, уже настроен или пропустить?
2. Какой endpoint использовать? Предложить `http://127.0.0.1:9000/mcp`.
   В dev-workplaces это localhost рабочего контейнера разработчика, не ноутбука
   и не общего сервера команды. Другой адрес использовать только по явному выбору.
3. Предложить имя регистрации по имени проекта и абсолютный путь к выгрузке
   (обычно `<корень проекта>/src/cf`). Уточнить, нужна ли отдельная регистрация
   расширения; не смешивать конфигурацию и расширение в одной записи без проверки.
4. Если записи ещё нет, предложить создать её. Пароль проекта RLM задаёт
   пользователь; это отдельный пароль, не пароль ИБ или хранилища 1С.
   Не генерировать его самостоятельно и не записывать в Git, отчёт или инструкции.
   Если безопасно передать пароль агенту нельзя, регистрацию выполняет пользователь.
5. Предложить построить индекс сейчас или отложить. Объяснить, что большая
   выгрузка требует времени и ресурсов. Согласие на регистрацию не является
   согласием на построение или пересоздание индекса.

## Действия агента

Быстрая подготовка: прочитать только параметры endpoint и EXPORT_PATH из локальной
конфигурации, проверить MCP и реестр, проверить состав указанного каталога.
Не выводить содержимое файлов с секретами. Не искать выгрузку рекурсивно по диску
и не исследовать устройство RLM при обычной регистрации. Если путь неизвестен —
спросить пользователя. Если в каталоге только README — сразу сообщить, что выгрузки
нет, и предложить отдельный экспорт. Установленный в контейнере сервер не требует
установки Python, uv или пакетов для каждого проекта.

- Проверить MCP initialize и tools/list. Обычный GET `/mcp` с HTTP 406
  не доказывает неисправность сервера. Если инструменты ещё не доступны,
  настроить endpoint и попросить переподключить MCP, не объявлять настройку готовой.
- На dev-workplaces проверить `systemctl --user status rlm-tools-bsl.service`.
  Там RLM устанавливается с рабочим образом. Не запускать установщик повторно
  и не поднимать второй процесс на порту 9000.
- Прочитать актуальную схему `rlm_projects`, выполнить `action=list`.
  Проверить имя и путь: совпадение — повторная регистрация не нужна;
  другое назначение того же имени — обсудить новое имя или изменение существующей
  записи. Чужую запись автоматически не изменять и не удалять.
- Проверить, что выбранный путь существует и содержит нужную выгрузку BSL/XML.
  При пустом `src/cf` отложить регистрацию/индексацию до выгрузки, а не индексировать
  весь репозиторий. Не запускать выгрузку из ИБ без отдельного согласования.
- После согласия выполнить `rlm_projects(action="add", name=..., path=...,
  password=...)` по актуальной схеме. При обновлении пути запросить согласие.
- Проверить существующий индекс через `rlm_index` по актуальной схеме.
  Строить/обновлять его только после согласования, передавая подтверждение,
  предусмотренное схемой. Индекс не удалять для обычной настройки.
- В отчёте указать endpoint, имя, путь, результат регистрации и состояние индекса
  либо причину отсрочки. Пароль не выводить. Личные пути не фиксировать в общих
  правилах проекта: источником регистрации является персональный реестр RLM.

## Правила дальнейшей работы

Настройка RLM не меняет порядок поиска: если graph или code-metadata доступны,
использовать их. RLM — резерв при недоступности обоих либо по прямому запросу
пользователя. Регистрация и диагностика при init допустимы независимо от этого.
Перед анализом читать `rlm_help`, использовать зарегистрированное имя проекта,
проверять актуальность индекса после изменения выгрузки и закрывать сессию
через `rlm_end`. Подробнее: [каталог инструментов](../.cursor/skills/mcp-1c-tools/docs/rlm-tools-bsl.md).

На dev-workplaces служба работает от имени разработчика, слушает только localhost,
а реестр, кэш и индексы находятся в домашнем томе. Пароль регистрации не следует
считать полноценной сетевой защитой MCP: порт не публиковать для других пользователей.
